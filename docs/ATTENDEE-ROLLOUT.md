# Attendee rollout — registration intake and account email

## Separate the three actions

An import creates private event registrations. It does not create login accounts, publish profiles, send invitations, or subscribe anyone to marketing. The attendee subsequently verifies their email and chooses profile visibility. An organizer-approved invitation rollout is a separate action after account-email delivery is qualified.

The September 30 live event currently contains four approved registrations, not the complete attendee cohort. The reviewed organizer emails have not supplied the full roster or Fun Stuff content. Do not substitute an unrelated mailing list or infer attendance from a CRM marketing segment.

## Import workflow

In **Admin > Attendees > Import attendees**, upload a CSV of up to 1,000 rows and 1 MB. Supported headings are `email` / `Email Address`, `name` / `Full Name`, or `First Name` plus optional `Last Name`. `phone` / `Phone Number` / `Mobile Phone` is optional and stays in the Admin-private contacts table. Extra columns are explicitly reported as ignored; roles and permission fields are never imported.

The preview shows new and existing registrations, already connected accounts, disabled/pending records, and Admin/Sponsor matches. Imports are **add-missing-only**. Existing names, phones, roles, access state, Auth ownership, directory permissions and profile visibility are kept unchanged. Correct existing data through its explicit organizer editor, not a spreadsheet re-upload.

Confirm the reviewed preview before importing. The server binds commit to the normalized file and the current matched records. A roster change requires a fresh preview. A lost response is not treated as a successful import; the UI rechecks existing registrations before allowing another write. Repeat imports create no duplicates and cannot reactivate disabled people.

Schema: `20260930222710_attendee_import_preflight.sql` and `20260930224400_attendee_import_conflict_status.sql`. They preserve the existing two-argument integration RPC while making repeat imports non-destructive, add a private normalizer plus Admin-only preview/commit RPCs, and retain event isolation, verified ownership checks, RLS and aggregate audit records. The preview checksum is a concurrency check, not an authorization secret. A stale preview uses explicit `PT409` rather than a database serialization error, so the hosted API returns a clear application conflict without implying an import succeeded.

## Account-email preparation

`supabase/templates/confirmation.html`, `invite.html` and `recovery.html` are generated by `scripts/build-account-email-templates.mjs`. All links go to the tested recipient-click confirmation page on `{{ .SiteURL }}`. Signup also includes a verification code and then routes to `/account-ready`, which chooses the correct event-role destination. No template uses a direct single-use provider verification URL or tracking redirect.

The source now includes the missing invitation template. A source file or a generated patch is **not** proof of deployed email configuration. `scripts/account-email-preflight.mjs` is read-only: it validates the source templates, probes the public release, and optionally compares a privately fetched hosted Auth configuration via `--hosted-config`. It writes a template-only Management API patch under ignored `test-results/account-email/`; it does not apply that patch, set a sender, or send mail.

Before opening `EVENT_BEAST_EMAIL_READY`, confirm the exact From and Reply-To addresses, install the three templates, configure domain-scoped SMTP credentials without logging them, verify canonical origins and confirmation settings, review provider/Auth send limits for the attendee wave, and test real signup, invitation and recovery in independent inboxes. Keep click/open tracking disabled for account mail. Retain the 12-character password rule and review hosted leaked-password protection.

The account-mail sender is **Momentum Builder LIVE 2026 <accounts@noreply.momentumbuilder.com>** using the verified `noreply.momentumbuilder.com` Resend sending domain. Production Auth uses `https://2026live.momentumbuilder.com` as its canonical site URL so new activation and recovery links remain on Sonia's final event host; `eventapp.momentumbuilder.com` and the former Vercel callbacks remain temporarily allowlisted only for already-issued links. Custom SMTP can be configured without opening the attendee email gate. Keep bulk invitations paused until real signup, invitation and recovery delivery are proven in independent inboxes.

Primary references: [Supabase email templates and prefetch behavior](https://supabase.com/docs/guides/auth/auth-email-templates), [custom SMTP restrictions and configuration](https://supabase.com/docs/guides/auth/auth-smtp), and [local template configuration](https://supabase.com/docs/guides/local-development/customizing-email-templates).

## Qualification

`tests/attendee-import-preflight.test.ts` runs 500 synthetic rows, repeat imports, stale previews, invalid rows, private contact/role preservation and authorization boundaries against actual migrations in PGlite. API tests cover same-origin checks, missing preview refusal and error responses. Browser checks use actual database fixtures for the review/confirmation/retry UI, with an explicitly simulated lost response.

`scripts/qualify-roster-intake.mjs` is the separate hosted rehearsal: it uses an unpublished isolated event and synthetic identities, validates a 500-registration import and repeat, checks non-Admin/cross-event refusal, then removes the test event and accounts. It does not alter the real event roster or qualify automatic inbox delivery. Inspect its JSON result before claiming hosted qualification complete.

The broader commercial SaaS roadmap remains post-event. This increment prepares the event's attendee onboarding; it does not add billing, tenant onboarding, SMS or marketing automation.
